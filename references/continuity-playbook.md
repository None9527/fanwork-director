# 故事连贯手册（混合模式）

连贯性有两层：**视觉连贯**（镜头间画面不断裂）和**角色连贯**（同一角色前后长得一样）。
混合模式用不同机制分别对付它们：

- 视觉连贯 → 末帧接力（FL2VA / I2VA with PREV_LAST）
- 角色连贯 → 角色参考图锚定（Phase 3 的 images/ 底图 + cast.md 外观锁定串；漂移时 Ref2VA 纠偏）

## 模式决策表（Phase 4 逐镜执行）

| 情形 | 模式 | 输入 |
|---|---|---|
| 场景首镜 | I2VA | Phase 3 生成的定制关键帧作 first_frame |
| 场景内后续镜，上一镜末帧构图能接 | FL2VA | prev_last 作 first_frame + 本镜定制 last_frame 关键帧 |
| 场景内后续镜，末帧自然衔接即可 | I2VA | prev_last 作 first_frame，无 last_frame |
| 纠偏：前镜角色漂移，本镜要拉回来 | Ref2VA | 角色 images/ 参考图 + 场景关键图，prompt 内声明保留关系 |
| 转场镜（时间/地点跳跃） | I2VA | 定制关键帧（不复用末帧，视觉重启） |

优先级判断顺序：先看末帧能不能接（接则接力，视觉最顺）→ 再看角色漂没漂
（漂则插入 Ref2VA 纠偏，代价是该镜视觉衔接弱化，用 anchor_in 文字补偿）。

## 末帧接力操作规程

```bash
python3 scripts/assemble.py lastframe clips/shot_01.mp4 refs/shot_02_first.png
```

- 默认取视频最后一帧；若末帧角色处于动作极端相位（糊帧/闭眼/大透视），
  用 `--at <秒>` 取末帧前 0.2–0.4s 的稳定帧，并在 anchor_in 里写明差异。
- 接力的下一镜 prompt 第一句必须描述与 first_frame 完全一致的运动起点
  （官方指南 base-en.txt 对 I2VA 的要求：从首帧正向发展）。

## 角色漂移纠偏三级火箭

1. **重roll**：同 prompt 重新生成（模型随机性可能就修好了）——最多一次。
2. **换帧位**：末帧接力改用更早的稳定帧；缩短该 shot 让漂移来不及发生（时长减半原则）。
3. **Ref2VA 拉回**：挂原始角色参考图纠偏，prompt 中按 ref-en.txt 格式写
   `subject_definitions`，明确 `<Picture 1>` = 角色 X 的相貌基准、
   `<Picture 2>` = 上一镜末帧的场景/站位基准，保留分析(retention_analysis)里
   声明"沿用场景与光线，仅重置主体相貌"。

三级都失败 → 改分镜（拆分该镜或改调度），在 ledger.md 记录并告知用户，不硬砸 API。

## 场景账本 ledger.md 格式

每完成一镜追加一行：

```
| shot | 末帧角色状态 | 光源方向 | 轴线 | 漂移标记 | 备注 |
|---:|---|---|---|---|---|
| 01 | 黑熊精画面左1/3面朝右 | 右后余烬红 | 未越轴 | 无 | |
| 02 | 同上，爪已抬起 | 右后余烬红 | 未越轴 | 轻微(毛发偏棕) | 已用--at 4.6取稳定帧 |
```

Phase 5 场景内串行执行时，写下一镜 prompt 前必须先读 ledger 末行，把状态写进 anchor_in。
